1. WHAT IS THIS TODOAPP?
====================================================================================================

This TodoApp is a full-stack web application that allows users to:
- Register and login with their email and password
- Create, read, update, and delete (CRUD) todo items
- Mark todos as complete or incomplete
- Set due dates for todos
- View statistics of pending and completed todos

Think of it like a digital notepad where you can write down tasks and check them off when done,
but with user accounts so each person has their own private list.

2. TECHNOLOGIES USED (WHAT AND WHY)
====================================================================================================

FRONTEND (What the user sees and interacts with):
- React.js: A JavaScript library for building user interfaces
  WHY: Makes it easy to create interactive web pages with components
- Vite: A build tool and development server
  WHY: Faster development and building compared to older tools
- Tailwind CSS: A utility-first CSS framework
  WHY: Quickly style components without writing custom CSS
- Axios: A library for making HTTP requests
  WHY: Easier way to communicate with the backend server

BACKEND (The server that handles business logic):
- Spring Boot: A Java framework for building web applications
  WHY: Provides structure and many built-in features for web apps
- Spring Security: Security framework for authentication
  WHY: Handles user login, passwords, and protecting routes
- JPA/Hibernate: Object-Relational Mapping (ORM)
  WHY: Lets us work with database using Java objects instead of SQL
- JWT (JSON Web Tokens): For stateless authentication
  WHY: Secure way to identify users without storing sessions

DATABASE:
- MariaDB: A relational database (similar to MySQL)
  WHY: Stores user data and todos permanently

┌─────────────────────────────────────┐

HOW THEY COMMUNICATE:
1. User clicks "Add Todo" in React app
2. React sends HTTP POST request to Spring Boot server
3. Spring Boot validates the request and saves to database
4. Database confirms the save
5. Spring Boot sends success response back to React
6. React updates the UI to show the new todo

7. AUTHENTICATION SYSTEM
====================================================================================================

WHAT IS AUTHENTICATION?
Authentication is the process of verifying who a user is (like checking an ID card).
Our app uses JWT (JSON Web Tokens) for authentication.

HOW JWT WORKS:
1. User logs in with email/password
2. Server verifies credentials against database
3. If valid, server creates a JWT token (like a temporary ID card)
4. Token is sent back to the client
5. Client stores token and sends it with every request
6. Server validates token on each request

JWT TOKEN STRUCTURE:
A JWT has three parts separated by dots:
header.payload.signature

Example: eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiJqb2huQGV4YW1wbGUuY29tIn0.signature_here

AUTHENTICATION FLOW IN OUR APP:

1. REGISTRATION:
   Frontend → POST /api/auth/register → Backend
   ├── Validate input data
   ├── Check if email already exists
   ├── Hash password with BCrypt
   ├── Save user to database
   ├── Generate JWT token
   └── Return token + user info

2. LOGIN:
   Frontend → POST /api/auth/login → Backend
   ├── Validate input data
   ├── Find user by email
   ├── Check password with BCrypt
   ├── Generate JWT token
   └── Return token + user info

3. PROTECTED REQUESTS:
   Frontend → GET /api/todos (with Authorization header) → Backend
   ├── Extract token from Authorization header
   ├── Validate token signature
   ├── Extract user email from token
   ├── Find user in database
   └── Process request for that user

STEP 4: LOGIN FUNCTION IS CALLED
─────────────────────────────────

File: src/auth/auth.jsx
```javascript
import { createContext, useContext, useState } from 'react'
import api from '../api/axios.js'

const AuthContext = createContext()

export function AuthProvider({ children }) {
    const [token, setToken] = useState(localStorage.getItem('token'))
    const [user, setUser] = useState(JSON.parse(localStorage.getItem('user') || 'null'))

    const login = async (credentials) => {
        const response = await api.post('/auth/login', credentials)
        const { token, user } = response.data
        
        setToken(token)
        setUser(user)
        localStorage.setItem('token', token)
        localStorage.setItem('user', JSON.stringify(user))
    }

    return (
        <AuthContext.Provider value={{ token, user, login, logout }}>
            {children}
        </AuthContext.Provider>
    )
}
```
WHAT HAPPENS:
- Sends POST request to backend with email/password
- If successful, saves token and user info
- Stores in localStorage so user stays logged in after page refresh
- Updates React state which triggers re-render

WHAT HAPPENS:

File: UserService.java
```java
@Service
public class UserService {
    
    public AuthResponse login(LoginRequest req) {
        // Step 1: Authenticate user
        authenticationManager.authenticate(
            new UsernamePasswordAuthenticationToken(
                req.getEmail(), 
                req.getPassword()
            )
        );
        
        // Step 2: Find user in database
        User user = userRepository.findByEmail(req.getEmail()).orElseThrow();
        
        // Step 3: Generate JWT token
        String token = jwtService.generateToken(
            user.getEmail(), 
            Map.of("role", user.getRole())
        );
        
        // Step 4: Create response
        AuthResponse.UserInfo userInfo = new AuthResponse.UserInfo(
            user.getEmail(), 
            user.getFullName()
        );
        return new AuthResponse(token, userInfo);
    }
}
```
WHAT HAPPENS:
1. authenticationManager checks if email/password is correct
2. If wrong → throws exception → user gets error message
3. If correct → finds user in database
4. Generates JWT token containing user email and role
5. Creates response object with token and user info

    User user = userRepository.findByEmail(userEmail).orElseThrow();
    
    Todo todo = new Todo();
    todo.setTitle(req.getTitle());
    todo.setDescription(req.getDescription());

3. Sets all the fields from the request
4. Links todo to the user
5. Saves to database using repository

STEP 10: TODO IS SAVED TO DATABASE
──────────────────────────────────

File: Todo.java (Entity)
```java
@Entity
@Table(name = "todos")
public class Todo {
    @Id 
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    
    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "user_id", nullable = false)
    @JsonIgnore
    private User user;
    
    @Column(nullable = false)
    private String title;
    
    // ... other fields
}
```
WHAT HAPPENS:
- @Entity tells JPA this class represents a database table
- @Id marks the primary key field
- @GeneratedValue means database will auto-generate the ID
- @ManyToOne creates foreign key relationship to users table
- @JsonIgnore prevents user object from being included in JSON response
- When todoRepository.save() is called, JPA generates SQL INSERT statement

Generated SQL:
```sql
INSERT INTO todos (user_id, title, description, due_date, completed, created_at, updated_at)
VALUES (1, 'Buy milk', 'Get milk from store', '2025-09-02 18:00:00', false, NOW(), NOW());
```

10. COMMON ISSUES AND SOLUTIONS
====================================================================================================

ISSUE: "Cannot read property of undefined"
CAUSE: Trying to access data that hasn't loaded yet
SOLUTION: Use optional chaining (todo?.title) or check if data exists

ISSUE: CORS error when calling API
CAUSE: Backend not configured to allow frontend domain
SOLUTION: Add CORS configuration in SecurityConfig.java

ISSUE: 401 Unauthorized error
CAUSE: JWT token expired or invalid
SOLUTION: Check token format, expiration, and secret key

ISSUE: Todos not displaying properly
CAUSE: Circular reference in JSON serialization
SOLUTION: Add @JsonIgnore to prevent infinite loops

ISSUE: Database connection failed
CAUSE: MariaDB not running or wrong credentials
SOLUTION: Check database server status and connection settings

ISSUE: "npm ERR!" or dependency issues
CAUSE: Package conflicts or outdated dependencies
SOLUTION: Delete node_modules, run npm install again

ISSUE: Java compilation errors
CAUSE: Missing imports or syntax errors
SOLUTION: Check imports, fix syntax, restart IDE
